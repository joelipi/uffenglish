# UFF — Ultra Fast Fluency

**UFF (Ultra Fast Fluency)** is a web app for learning English fluency through speaking and listening. Learners work through video lessons built around a native-speaker role play, answer voice-first, and receive AI evaluation of intent/grammar plus a fluency score (0–100). It is built for learners who want to speak rather than tap through drills. Learners record themselves per step and receive a shareable end-of-lesson recap video; the friend-challenge loop lets a learner invite a friend to answer their recorded questions within a 48-hour window.

## Features

- **Voice-first role-play lessons** — native-speaker video sets the context, the learner answers by voice, and speech-to-text plus AI feedback scores each response ([answer-flow](tests/answer-flow.spec.js)).
- **Bilingual overlays** — cues and subtitles localized to the learner's L1 (en/es/pt/fr, plus targeted hi/bn keys).
- **Auto-generated simple-video captions** — new `simpleVideoUrl` videos get English SRT from local Whisper plus DeepSeek translations to es/pt/fr/hi/bn, committed to the branch on push ([story](stories/009-auto-caption-simple-videos/story.md)).
- **Lesson recap video** — client-side stitched end-of-lesson recap (model prompts + own recordings) with a fluency score card, generated via canvas + MediaRecorder.
- **Stale-deploy recovery** — if a new deployment replaces the hashed JS chunks while a tab is still open, the next failed dynamic import triggers a bounded one-time reload (max 2 per tab) so the learner gets the new build instead of a `'text/html' is not a valid JavaScript MIME type` error ([story](stories/030-reload-stale-chunk/story.md)).
- **Recap subtitles always burn the matched cue for closed responses** — a learner's recorded answer for a closed-response step is subtitled with the matched cue variant when their transcript matched one (the canonical answer from `src/config`) and with no subtitle when none matched, but never the raw speech-to-text transcript, so recognition errors do not appear on the exported video; the per-segment R2 clips use the same plan ([story](stories/028-burn-cue-not-transcription/story.md)).
- **Friend clips keep their own caption in the recap** — a `remote` segment whose clip is a friend's published UGC video (slug ending `-response-NN`, i.e. a friend lesson's recorded prompts) gets no subtitle from the recap, because that clip already carries its own speaker's caption burned in when it was published per-segment; overlaying the response step's cue would stamp the current user's answer onto the friend's question video. The current user's own `webcam` segments keep the matched-cue rule ([story](stories/036-fix-friend-lesson-subtitles/story.md)).
- **Concatenated recap published to R2** — when a logged-in learner finishes a lesson that publishes segments, the stitched recap is also uploaded to R2 under the same `videos/` namespace (48h TTL) as `videos/<shareCode>-<courseId>-<lessonId>-complete.mp4`, for every lesson including the friend ask/answer lessons `a`/`b`; the upload is best-effort and skipped when the transcoded file exceeds the Function's 50 MB cap ([story](stories/021-upload-concatenated-videos-to-r2/story.md)).
- **Per-segment clips published by trimming the recap recording** — when a logged-in learner finishes a lesson that publishes clips, each publishable webcam step's time range is recorded during the single recap render, and the per-segment clips are produced by trimming that recording (`WebCodecs`/`mediabunny`) and uploading them to R2; no second render pass is run. The clips carry the recap overlay (the share headline on `w`/`wf`, and the opening fluency card on the first clip) and keep the 1080×1920 composite with burned (dynamic) cues ([story](stories/035-single-pass-clip-publish/story.md)).
- **Prominent concat button on the success screen** — the end-of-lesson "make my video" trigger stays hidden while the short success clip plays, then is revealed as a large, glowing CONTINUE call-button under a water overlay that invites the learner to create and share their video, matching the earlier decision steps ([story](stories/011-enlarge-concat-button/story.md)).
- **Landscape recording warning** — on iOS/Android, a dismissible banner tells the learner to rotate the device to portrait while it is held landscape, so recorded clips keep the intended 9:16 framing ([story](stories/015-warn-landscape-recording/story.md)).
- **Friend Challenge lessons** — a course's lessons form a ping-pong chain (`wouldrather`/`friendchain`). The ask lesson lets a learner record "Would you rather?" questions, share a link, and the answer lesson lets a friend answer; the two clips are concatenated. The asker's 3 question clips publish to R2 (48h TTL) and friends answer them via a `?sharecode=` URL.
- **Friend-challenge practice link** — after an ask video is exported, the creator's public profile (`/:shareCode`) shows "Practice English with Me" links to the matching answer lessons, each with a 48h countdown that removes it when the R2 clips expire; there is one link per recorded lesson ([story](stories/012-friend-lesson-link/story.md), [044](stories/044-per-lesson-profile-links/story.md)).
- **Public homepage + user home split** — `/` is a public share-code homepage for everyone (headline, subheadline, input, a Go button, and an "I don't have a share code" button); Go looks the code up first and opens the matching public profile `/:shareCode`, showing an inline "friend code not found" message otherwise, while the no-code button starts the Would You Rather ask lesson at `/course/wouldrather/lesson/a`. The user dashboard (`HomeScreen`: menu, course card, notification bell, Continue) moves to `/home`, post-login/sign-up redirects default to `/home`, and the guest language/login modal no longer opens on `/` ([story](stories/045-homepage-share-code/story.md)).
- **Friend-response notifications** — when a friend opens an asker's share link and exports the answer video, the asker gets an in-app notification in a bell menu on the home screen, with a timestamp, a static "You only have 48 hours to respond" line (the elapsed time is visible from the timestamp), and a link to the friend's public profile (`/<shareCode>`); notifications are stored in Supabase, deduped per friend, and mark-as-read ([story](stories/019-notify-share-link-video-created/story.md)).
- **Responders become challengers** — legacy behavior in `src/config/friend.json` only: the ask questions are appended to the end of answer lesson `b` (tagged `publishLessonId: "a"`), so the same `b` export publishes the responder's own question clips under lesson `a`. The chain code no longer consults `askPublished`; friend lessons after the first chain lesson (`a`) now create their profile link directly ([story](stories/015-b-lesson-ask-clips/story.md)).
- **Friend-challenge chain** — friend lessons form an ordered ping-pong `a, b, c, …`: the chain is the `recapOverlay: "shareCta"` lessons in `configData.lessons` order, finishing lesson X records a profile share link pointing at X+1, a friend-response notification fires for every chain lesson after the first, and the public profile lists one labelled link per in-flight lesson (label from the lesson title). Friend mode never auto-advances — `nextLessonId` stays single-user-only ([story](stories/043-extend-friend-lesson-chain/story.md)).
- **Per-lesson profile links** — the public profile lists one link per lesson whose prompts the owner recorded (not one per course), grouped under a course-name heading. Each link is labeled with the recorded lesson's **English** title (lesson titles are no longer localized) and opens the follow-on lesson with the owner's `?shareCode=`, so a visitor can pick the prompt set they remember. Entries are keyed `courseId:recordedLessonId` in the `friend_links` jsonb map and expire on the same 48h window; the "already played" state relies on the browser cache, with no new storage ([story](stories/044-per-lesson-profile-links/story.md)).
- **Auto-advancing friend answers** — answering a friend's question correctly advances straight to the next step with no feedback pause; incorrect answers retry via the hangman hint until correct ([story](stories/005-skip-friend-feedback/story.md)).
- **Friend prompts survive click-through presentation** — when a friend-challenge lesson shows the friend's clip as a non-interactive click-through step before the explanatory response step, the recap still concatenates the friend's question clips onto the recorded answer ([story](stories/016-recap-friend-prompt-clips/story.md)).
- **Low-friction friend lessons** — a lesson opened via a friend link (`?shareCode=`) or with a single-letter chain lesson id (`a`–`z`) never auto-opens the guest login step: a non-English browser language is adopted silently, and only an English browser sees the language-confirmation step (which then closes, no Log In / Sign Up prompt). Login stays available after recording or from the menu ([story](stories/016-friend-lesson-modals/story.md)).
- **Friend lessons are video-only** — for a friend lesson (`?shareCode=` in the URL, or a lesson whose id is `a`/`b`), the first-response mode chooser hides Audio Only and Text Only and leaves only the Video Call button, so the recorded clip can become the shared video the lesson exists for ([story](stories/020-friend-video-only/story.md)).
- **Simple-video response decision overlay** — a response step (`closedResponse`/`openResponse`/`friendClosedResponse`) whose only clip is a `simpleVideoUrl` hides the mic while the clip plays (freeing the bottom band for its subtitles) and then, once the clip ends or fails to load, raises the Replay / Answer / Tutorial water overlay; closed responses use the "repeat exactly" copy and label, open responses the "did you understand?" copy and "respond now" label ([story](stories/028-friend-response-video-overlay/story.md)). On a friend lesson (`?shareCode=` link or lesson id `a`/`b`, detected route-only) the first response step skips the one-button mode chooser and uses the same flow, so question one behaves like the rest ([story](stories/029-friend-first-question-overlay/story.md)).
- **Correction card dismisses on re-record** — the "Try again" hangman correction card hides as soon as the learner presses the microphone button to record their retry ([story](stories/014-hide-correction-box-on-re-record/story.md)).
- **Share-CTA recap** — ask-only lessons render a webcam-only "ad" recap with a localized headline, 48h deadline, and single-line share URL ([story](stories/001-webcam-only-share-cta/story.md)).
- **Per-lesson recap controls** — each lesson's recap overlay (`recapOverlay`: `fluency` / `shareCta` / `none`) and concatenated prompt sources (`recapSources`: `system` / `friend` / `none`) are configured per lesson and are independent; the former `webcamOnly` flag is retired ([story](stories/010-recap-overlay-flag/story.md)).
- **Static intro-video step** — `wf` replays the intro clip as a non-interactive step with localized subtitles before the first recording step ([story](stories/003-add-wf-video-player-step/story.md)).
- **First lesson video gets load priority** — at lesson start the first distinct step video is prefetched at high priority while the remaining lesson videos are deferred until idle at low priority, and the intro `<video>` only preloads metadata on every platform, so Windows/Android no longer stall behind the bulk prefetch of all lesson videos ([story](stories/031-fix-slow-first-video-load/story.md)).
- **Uniform R2-only video posters** — every poster is a 0.2s still of its video and is the video's URL with `.mp4`→`.jpg` (`getPosterUrl(slug) = getVideoUrl(slug).replace('.mp4','.jpg')`); teacher/lesson-intro posters for every `src/config/*.json` course are generated and uploaded on push by `deploy.yml`, and user-generated friend clips upload a sibling `.jpg` at publish time. A poster is regenerated when it is missing or when its source `.mp4` is newer than the published `.jpg` (R2 `Last-Modified`), so replacing a video under the same slug refreshes its poster on the next push ([story](stories/011-auto-intro-poster/story.md), [regenerate stale posters](stories/025-regenerate-stale-posters/story.md)). No posters are committed to the repo or served locally.
- **Web-optimized lesson media** — a manual `scripts/optimize-videos.mjs` CLI remuxes every config-referenced lesson video to `+faststart` and re-encodes only clips over a 720px / ~1.5 Mbps budget, then uploads back over the slug (`videos:optimize` / `videos:optimize:upload`), so oversized or non-faststart R2 clips no longer stall first playback ([story](stories/032-optimize-r2-videos/story.md)).
- **Poster becomes the profile picture** — when a user has no profile picture (a fresh signup or an existing user whose `profile_picture_url` is null), finishing a lesson that publishes a poster copies that still (the first answer's `thumbBlob`) into the persistent Supabase `avatars` bucket and sets it as the profile picture; a user who already has a picture is never overwritten ([story](stories/019-use-poster-as-profile-picture/story.md)).
- **Text-mode fallback** — last-resort typed answers render avatar-card segments in the recap; text is only offered after the speech engine definitively fails (voice-first product rule). Friend lessons are the exception: they force video and never offer text or audio-only ([story](stories/020-friend-video-only/story.md)).
- **Branded loading screen** — startup shows the UFF logo over a blue gradient with a progress bar, from the inline HTML preloader through the React overlay; both load the logo from an existing bundled asset rather than a missing `/logo.png` path ([story](stories/024-fix-preloader-logo/story.md)).
- **Guest mode** — learners can start a lesson without logging in; UI strings and lesson content fall back to English when a translation is missing. Supabase accounts get a shareCode, profile, and R2 publish rights. A language the guest chooses (or that is silently adopted) is authoritative for the session and survives the asynchronous profile bootstrap, so the whole app — including the recap — stays in that language ([story](stories/023-guest-language-survives-bootstrap-profile-write/story.md)).
- **Guest language prompt** — the initial guest language-selection step leads with "Practice English with Us Free! / Select your language for translations", removes English from the dropdown (an English browser starts unselected and must pick a language or use an explicit exit), and frames the two non-translation exits as "No translations (not recommended)" and "My language is not on this list (continue without translations)" ([story](stories/037-guest-language-modal-copy/story.md)).
- **Pre-video signup gate** — the signup modal shown when a guest presses create-video hides its "Not now" button via CSS (the element stays in the DOM), so the modal reads as a signup gate; the first/last name fields in both signup forms align with the full-width email/password fields because the missing `.col-6`/`.col-md-6`/`.mt-md-0` grid classes are added to the hand-written stylesheet ([story](stories/034-hide-signup-skip-button/story.md)).
- **Bounded memory across repeated voice answers** — the unused per-step recording-chunk copy is dropped and the Whisper engine-readiness poll is cleared on step change, so repeated mic taps in a long lesson can no longer leave stale polling intervals running ([story](stories/038-fix-whisper-repeated-use-slowdown/story.md)).
- **Cloud lesson-video pipeline (authoring)** — the operator's phone recorder uploads takes to Cloudflare R2 (`raw/`), an operator-key-protected Pages Function starts a Modal render (reusing the existing T4 BiRefNet function) for a filename set, and the Modal app runs the silence/background/render stages, publishing `assets/videos/<slug>.mp4` plus a poster and writing a status marker the recorder polls; this is the teacher-media authoring path, not learner recaps, which stay client-side ([story](stories/040-modal-lesson-video-pipeline/story.md)).
- **Raw takes are private** — unpublished phone takes, pipeline-asset inputs and the render status marker live in a separate, non-public R2 bucket (`PIPELINE_R2` binding, default `uff-private`) that the public CDN `r2.ultrafastfluency.com` cannot serve; only published `assets/videos/...` and learner/UGC `videos/...` stay in the public `uff` bucket. Raw keys self-expire via an R2 lifecycle rule while `videos/` keeps its 48h TTL ([story](stories/041-private-raw-takes/story.md)).
- **Course configs generated from the published sheet** — an operator-invoked Node CLI (`scripts/generate-config-from-sheet.mjs`, no new deps) fetches the published Google Sheet CSV, groups rows by the `video_file` column (the config's `simpleVideoUrl`), and writes a **new** `src/config/<courseId>.json` from explicit structural sheet columns, consuming exact SRT timings from the pipeline's `srt` column when present; it **overwrites** an existing `src/config/<courseId>.json` (the sheet is authoritative — no `--force` gate); its output is English-only unless the sheet carries the per-language columns (the [049](stories/049-translate-sheet/story.md) translation round-trip fills `*_es/_pt/_bn`, which the generator then emits as `{en,es,pt,bn}`), so the sheet becomes the source of truth for both videos and configs ([042](stories/042-generate-config-from-sheet/story.md), [047](stories/047-overwrite-configs/story.md)).
- **Auto-generated configs, one per course, committed by CI** — a GitHub Action (`.github/workflows/configs.yml`, run via the "Generate Course Configs" workflow button, no local commands) generates one `src/config/<courseId>.json` per course the sheet defines (partitioned by `course_id`) and commits any changes; it is best-effort — a course with any missing required column is skipped whole and reported (which columns, where) without blocking the other courses or the video render, and the same workflow already accepts a `repository_dispatch (render-complete)` event for a later hands-off trigger ([story](stories/046-auto-generate-configs/story.md)).
- **Course configs auto-committed by GitHub Actions** — a `configs.yml` action (manual "Run workflow" now; prepared for a later Modal→GitHub `repository_dispatch`) regenerates configs from the sheet and commits them with the captions-bot pattern (PAT checkout, `[skip configs]` loop guard, commit only on a diff). A sheet may define **several courses**: each is generated independently into its own `src/config/<courseId>.json`, and a course whose required columns are incomplete is **skipped whole** (never a partial config) with a precise `SKIP course "…": missing required column(s): …` report; skips are non-fatal so the already-completed video render is never blocked ([story](stories/046-auto-generate-configs/story.md)).
- **The sheet is authoritative — generated configs overwrite** — a sheet-defined course's `src/config/<courseId>.json` is regenerated and **overwritten unconditionally** on every run (the `--force` gate and flag are gone); the CI action therefore propagates later sheet edits to an already-generated course, and the write goes through a same-directory temp file + rename so a killed run cannot leave a half-written config. Because generated configs are English-only, overwriting a hand-authored/localized course drops its es/pt/bn translations — an accepted consequence of "the sheet is the source of truth", not a guarded refusal ([story](stories/047-overwrite-configs/story.md)).
- **Sheet translations round-trip (en→es/pt/bn) written back by a GitHub Action** — the published Google Sheet stays the operator's editing surface; a manual `workflow_dispatch` Action (`.github/workflows/translate-sheet.yml`) reads the English source columns (`lesson_title`, `mission`, `cue`, `cue_alt`, `subtitle_text`) with a Google service account (scope `https://www.googleapis.com/auth/spreadsheets`), translates any **blank** target cells with the existing DeepSeek client (`translateText`, `deepseek-v4-flash`, taught English target phrase preserved), and writes them back in one `spreadsheets.values.batchUpdate` as per-language columns (`lesson_title_es`, `mission_pt`, `cue_es`, `cue_alt_es`, `subtitle_text_bn`, … — one column per language per field, 15 in all). The generator then reads those columns into `{en,es,pt,bn}` objects on `title`/`mission`/`cue`/`subtitles`, so the sheet now holds the translations the app localizes from. Translation only fills blanks (idempotent), so a human edit to a translation cell is honored by the next config generation; the English source is never overwritten and `srt` is never translated (captions own timing) ([story](stories/049-translate-sheet/story.md)).

## Non-Goals

- Native mobile apps — the codebase targets the web; React Native variants exist but are not shipped.
- No text-mode publishing path — typed answers are a practice fallback, never shareable UGC.
- Real-time human tutoring or live conversation.
- Authoring tools for teachers; lesson content is edited directly in `src/config/*.json`.
- No full localization beyond en/es/pt/fr (plus targeted hi/bn keys); profile supports many more locales than the UI is translated into.
- No server-side video rendering — recaps are generated entirely client-side.

## Known Limitations

- Text-mode users cannot publish clips (null blobs are filtered from the R2 export), so a friend opening their share URL gets a 404 lesson; the share CTA still renders over their avatar-card recap.
- `hi`/`bn` are partial localizations — most UI strings fall back to English for those users.
- Speech recognition runs Whisper in-browser and requires COOP/COEP and cross-origin headers; videos and Whisper fail on staging without the Cloudflare Transform Rules (`docs/cloudflare-video-cors.md`).
- Mic/camera cannot be exercised headlessly; many flows require the documented test bypasses (`agents.md`).
- Lesson media is hosted on Cloudflare R2 (`assets/videos/<slug>.mp4`); video files are gitignored (too large for the repository) and uploaded out of band, so lesson video playback depends on R2 availability and on the real recordings having been uploaded.
- Lesson-intro posters follow the same `<video>.jpg` sibling rule and are R2-only (`assets/videos/<slug>.jpg` for teacher intros, `videos/<…>.jpg` for UGC); teacher posters are generated/uploaded on push for every course and UGC posters at publish, so nothing is committed or served locally and a poster is only as available as R2 ([story](stories/011-auto-intro-poster/story.md)).
- The lesson-intro overlay no longer shows a caller name/title — the hardcoded "Joe Walsh / English Coach, UFF" was removed because it is wrong for friend/UGC intros. Surfacing the friend's own name (from their profile, via the share code) is deferred ([story](stories/013-remove-intro-caller-name/story.md)).
- Playwright's bundled Chromium lacks H.264/AAC codecs; video specs must run real Chrome (`agents.md` §5).
- The R2 UGC 48h TTL is configured in the Cloudflare dashboard, not in `wrangler.toml` (`README.md:98`).
- Classroom/staging testing depends on R2 availability; video playback cannot be fully verified offline.
- "Friend lesson" detection is route-based (`?shareCode=` in the URL, or a single-letter lesson id `a`–`z`) and does not include the course id, because course ids are open-ended. As a result any future course with a single-letter lesson id would be treated as a friend lesson: it would skip the automatic guest login/language prompt and be restricted to video-only mode ([story](stories/016-friend-lesson-modals/story.md), [020](stories/020-friend-video-only/story.md), [043](stories/043-extend-friend-lesson-chain/story.md)). The known single-user courses were renamed off single letters (`model`, `gt2`, `t`, `test-api`), so none is affected today.
- The friend-challenge chain is derived generically from `recapOverlay: "shareCta"` lessons in config order. `model.json` is a single-user course and contains no `shareCta` lessons, so it never chains ([story](stories/043-extend-friend-lesson-chain/story.md)).
- A guest who silently adopts a browser language on a friend lesson and then logs in within the same SPA session can keep that adopted language in memory until the next full page load; a page load while already logged in uses the profile language and skips all friend-lesson logic ([story](stories/016-friend-lesson-modals/story.md)).
- The automatic poster-to-profile-picture assignment only fills a null/placeholder slot; a stored `profile_picture_url` that is non-null but broken (e.g. a legacy `appwrite.io` URL) is treated as "has a picture" and is not replaced — a separate cleanup would be needed ([story](stories/019-use-poster-as-profile-picture/story.md)).
- The concatenated recap upload is best-effort and capped at the Cloudflare Function's 50 MB per-object limit; a longer lesson whose stitched mp4 exceeds 50 MB is silently skipped (logged + tracked), so its complete video is not published even though its per-segment clips are ([story](stories/021-upload-concatenated-videos-to-r2/story.md)).
- Recorded-clip subtitles burn the cue only for closed-response steps; an open-response answer has no canonical cue to match and still burns the transcript ([story](stories/028-burn-cue-not-transcription/story.md)).
- Per-segment clip publishing (trim, transcode and upload) completes while the page stays alive, including backgrounded or unfocused; if the OS force-closes, freezes, or discards the tab before it finishes, the remaining clips are not uploaded, and there is no cross-browser background-sync or resume path ([story](stories/035-single-pass-clip-publish/story.md)).
- Per-segment clips are cut from the recap recording using wall-clock step time ranges calibrated against the recording duration; a boundary miscalibration could trim a word, so the cut points are validated on real devices ([story](stories/035-single-pass-clip-publish/story.md)).
- A friend clip has no burned-in caption when its asker recorded before the caption rule or never matched a cue, so its recap segment then shows no subtitle; the current user's cue is deliberately never used as a fallback on the friend's clip ([story](stories/036-fix-friend-lesson-subtitles/story.md)).
