# Regenerate stale lesson posters

## Context

Teacher/lesson-intro posters are R2-only stills generated by `scripts/generate-thumbnails.mjs` and uploaded on every push by `deploy.yml`. Today `planPosterRun` (`scripts/lib/poster-utils.js`) selects a slug only when its poster is **absent** on R2 (`r2PosterExists`, a HEAD). `deploy.yml` runs the generator **without** `--force`, so when a video is replaced on R2 under an existing slug its poster is never regenerated and stays stale forever. `--force` exists but CI never uses it (and would regenerate every poster on every push, defeating the incremental design).

Real instance: the Friend Challenge course `src/config/wouldrather.json` lesson `a` uses first-step `introBackgroundVideoUrl: "testvideointro"`. Its poster `assets/videos/testvideointro.jpg` is a 0.2s still of `assets/videos/testvideointro.mp4`.

- video `last-modified`: `Mon, 28 Sep 2026 02:27:08 GMT`
- poster `last-modified`: `Sun, 27 Sep 2026 22:11:43 GMT`, 35684 bytes
- a freshly generated frame differs from the published poster (SSIM 0.708, 21376 bytes)

So the live poster is from the previous video. This story makes generation **freshness-aware**: on every push a slug is regenerated and re-uploaded when its source `.mp4` is newer than the existing `.jpg`, not only when the poster is missing. No API, UI, or deploy-workflow change is needed — only the planner, the CLI, tests, docs, and one regenerated derived artifact.

## Out of Scope

- No R2 deletion logic (stale objects are overwritten in place, never removed).
- No new npm dependencies.
- No change to UGC poster upload (`functions/api/upload-segment.js`) or to the client poster URL rule (`getPosterUrl`).
- No staleness change to `scripts/verify-thumbnails.mjs`; its gate stays existence-only (it must keep passing after `--upload`).
- No semantic change to `--force` (still targets every intro slug) or `--upload` (still uploads whatever the generate step wrote to the work dir).
- No change to `.github/workflows/deploy.yml`; its generate → `--upload` → verify sequence already picks up a regenerated work-dir poster.
- No live R2 writes by the implementer: writing the refreshed poster to R2 is done by the deploy pipeline, which holds the Cloudflare secrets.

## Implementation approach

All logic stays split as today: pure planning in `scripts/lib/poster-utils.js` (unit-testable, no new I/O), process/network in `scripts/generate-thumbnails.mjs`. `isPosterStale` is the single source of the freshness rule; the CLI supplies both timestamps from HEAD responses.

### Freshness rule (`isPosterStale`)

New pure export in `scripts/lib/poster-utils.js`:

```js
export function isPosterStale({ videoLastModified, posterLastModified } = {}) {
    const video = toTimestamp(videoLastModified);
    const poster = toTimestamp(posterLastModified);
    if (video === null || poster === null) return false;
    return video > poster; // strictly newer
}
```

where `toTimestamp(value)` accepts `Date | string | number` and returns epoch ms or `null`:

- `null` / `undefined` → `null`.
- `Date` → `value.getTime()`.
- `string` / `number` → `new Date(value).getTime()`.
- any non-finite result (`NaN`, i.e. an invalid date string) → `null`.

Consequences: missing/invalid on **either** side → `false` (never stale — fail safe, preserve existing poster); equal timestamps → `false`; only a strictly newer video → `true`.

### Planner (`planPosterRun`)

Extend additively, preserving the current signature and output shape:

```js
export async function planPosterRun({ configs, posterExists, posterStale = () => false, moduleText }) {
    const all = introTargets(configs);
    const exists = await Promise.all(all.map((t) => posterExists(t.slug)));
    const stale = await Promise.all(
        all.map((t, i) => (exists[i] ? posterStale(t.slug) : false)),
    );
    const targets = all.filter((_, i) => !exists[i] || stale[i]);
    const moduleMissing =
        moduleText == null ||
        all.some((t) => !moduleText.includes(`"${t.slug}"`) && !moduleText.includes(`'${t.slug}'`));
    return { targets, rebuild: moduleMissing || targets.length > 0 };
}
```

- `posterStale` is optional and awaited, so a `Promise<boolean>` works exactly like `posterExists`.
- `posterStale` is invoked **only** for slugs whose poster exists; an absent poster is already a target and is never stale-checked.
- Omitting `posterStale` (default `() => false`) reproduces today's behaviour byte-for-byte.
- `rebuild` semantics are unchanged: `targets.length > 0` OR the LQIP module is missing an intro slug OR `moduleText == null`.

### CLI (`scripts/generate-thumbnails.mjs`)

- Add `headObject(url)` returning `{ ok, lastModified }`; `lastModified` is `res.headers.get('last-modified')`, and any thrown/network error resolves to `{ ok: false, lastModified: null }`.
- Refactor `r2PosterExists(slug)` to `return (await headCached(posterHeadUrl(slug))).ok` — same signature and same true/false semantics as today.
- A tiny module-level `headCache` (`Map<url, Promise<{ok,lastModified}>>`) backs both the existence check and the staleness check so the poster URL is HEADed once per run.
- Both the source-video HEAD and the poster HEAD use `CDN_POSTER_BASE` (the existing `POSTER_CDN_BASE` env seam, default `https://r2.ultrafastfluency.com/assets/videos/`). `posterSourceUrl(slug)` gains an optional `base` argument (default unchanged), so the video HEAD is `posterSourceUrl(slug, CDN_POSTER_BASE)` — one definition of the `<slug>.mp4` path shared with the download — and the poster HEAD is `${CDN_POSTER_BASE}${posterFilename(slug)}`. `resolveSource` still downloads via `posterSourceUrl(slug)`.
- `r2PosterStale(slug)` HEADs both URLs (via the cache), calls `isPosterStale({ videoLastModified, posterLastModified })`, and logs `STALE <slug>: <slug>.mp4 is newer than <slug>.jpg` when true. The log fires during planning, i.e. before the `GEN <slug>` line it triggers, so both are greppable in CI output.
- `main` always passes `posterStale: r2PosterStale` into `planPosterRun`; under `--force` `posterExists` is `() => false` so every slug is targeted and the staleness predicate is never consulted (it only runs for slugs whose poster exists).
- When a staleness HEAD yields no `Last-Modified` (transient R2/DNS failure), the rule stays fail-safe (`false`) but logs `WARN <slug>: missing Last-Modified … — freshness not checked` so a skipped refresh is visible.

### LQIP module

`src/generated/poster-lqips.js` is the only poster-derived artifact in git. Because `plan.rebuild` is now true when `testvideointro` is stale, one real run of `node scripts/generate-thumbnails.mjs` (ffmpeg + R2 reachable; no Cloudflare creds needed) rewrites it with the refreshed `testvideointro` LQIP. `.jpg` files are never committed (work dir is outside the repo).

## Tasks

### Task 1 - Add pure `isPosterStale` to `scripts/lib/poster-utils.js`

- `isPosterStale` is exported from `scripts/lib/poster-utils.js`.
  - → importing the module exposes a function named `isPosterStale`.
- video timestamp strictly newer than poster timestamp (strings `'2026-09-28T02:27:08Z'` vs `'2026-09-27T22:11:43Z'`) + call
  - → returns `true`.
- video timestamp older than poster timestamp + call
  - → returns `false`.
- video timestamp equal to poster timestamp + call
  - → returns `false` (strict comparison).
- `videoLastModified` or `posterLastModified` is `null`, `undefined`, or omitted + call
  - → returns `false`.
- either value is an invalid date (`'not-a-date'`, `new Date('nope')`, `NaN`) + call
  - → returns `false`.
- values supplied as `Date` objects and as epoch-number milliseconds + call
  - → interpreted as timestamps and compared correctly (newer `Date`/number → `true`).

### Task 2 - Extend `planPosterRun` with optional `posterStale`

- all posters exist, module complete, `posterStale` returns `true` for exactly slug `a` + call
  - → `targets` is `[{ slug: 'a' }]`.
  - → `rebuild` is `true`.
- all posters exist, module complete, `posterStale` returns `false` for every slug + call
  - → `targets` is `[]` and `rebuild` is `false`.
- all posters exist, module complete, `posterStale` omitted + call
  - → `targets` is `[]` and `rebuild` is `false` (existing behaviour preserved).
- `posterExists` returns `false` for slug `a` and `true` for slug `b`; `posterStale` is a spy + call
  - → `targets` is `[{ slug: 'a' }]`.
  - → the spy was called with `b` only, never with `a` (an absent poster is never stale-checked).
- `posterStale` is `async` and resolves `true` for a slug whose poster exists + call
  - → that slug is targeted (the planner awaits the promise rather than treating it as always-truthy).
- `posterExists` returns `true` for all, `posterStale` returns `false` for all, `moduleText` is `null` + call
  - → `targets` is `[]` and `rebuild` is `true` (module-missing rule unchanged).
- `posterExists` returns `true` for all, `posterStale` returns `false` for all, module omits slug `a` + call

### Task 3 - Wire freshness into `scripts/generate-thumbnails.mjs`

## Technical Context

- No new dependencies. Runtime is Node 20 in CI (`deploy.yml`) with global `fetch` (undici); `last-modified` is read from the response headers. Local dev/tests use the `vitest` already in `package.json` (`vitest ^4.1.6`).
- `ffmpeg`/`ffprobe` are required only by the generator and the integration test (CI installs ffmpeg before `npm test`; the integration describe is `describe.skip` when ffmpeg is absent). Verified present locally: ffmpeg 6.1.1.
- `POSTER_CDN_BASE` is the pre-existing test seam (default `https://r2.ultrafastfluency.com/assets/videos/`); `POSTER_OUT_DIR` and `POSTER_LQIP_PATH` remain the work-dir/module seams. Both `generate-thumbnails.mjs` and `verify-thumbnails.mjs` already define `CDN_POSTER_BASE`; the generator's new HEADs reuse it.
- R2 HEADs are public (no credentials); the implementer can generate/download locally. Writing refreshed posters to R2 is exclusively the deploy pipeline's job (`CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` GitHub secrets are absent from this environment).
- The six current first-step intro slugs are `testvideo01`, `do_you_have_rolls_too`, `do_you_have_dark_chocolate`, `gtests-1-0`, `testvideointro`, `gtests-0-1-1`; only `testvideointro` is stale per the R2 `last-modified` values above.
- `deploy.yml` is intentionally unchanged: `Generate posters` writes the fresh `testvideointro.jpg` to the shared `os.tmpdir()/uff-posters` work dir, `--upload` pushes `allTargets` from that dir (skipping files absent from it), and the following `verify-thumbnails.mjs` existence gate then passes.
- Rebase/branch caution (`agents.md` §32, §36): run `git branch --show-current` before committing; the shared worktree can switch branches mid-task.

## Notes

- `isPosterStale` must never be consulted for a missing poster; existence is the target signal. This keeps the common first-run path (all posters absent, e.g. the existing fake-R2-404 integration test) from issuing extra video/poster HEADs.
- The stale log is intentionally `STALE <slug>` (uppercase prefix, matching `GEN`/`UPLOAD`) so it is greppable in CI output.
- `lqipFor` downloads each non-regenerated poster into the work dir before downscaling it, so after any run with work the work dir contains every poster and the following `--upload` re-uploads all of them (pre-existing behaviour, idempotent). The integration test therefore asserts generation via the `GEN` stdout line, not by file presence in the work dir.
- `verify-thumbnails.mjs` is deliberately left existence-only: it runs after `--upload`, so a regenerated-and-uploaded poster already satisfies it; adding its own staleness gate would fail the pipeline whenever R2 clock/headers are unavailable.
- The one real `node scripts/generate-thumbnails.mjs` run in Task 4 is the only step that must reach R2 and cannot be replaced by a unit test; its outcome is checked with `git diff`.
